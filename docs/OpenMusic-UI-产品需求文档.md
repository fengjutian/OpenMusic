# OpenMusic UI/UX 产品需求文档

> 版本：V2.0  
> 日期：2026-10-09  
> 状态：可进入设计与开发  
> 产品定位：本地优先、Android 与 Windows 双平台、面向中文用户的沉浸式音乐播放器

## 1. 文档目的

本文件定义 OpenMusic 新版 UI 的产品范围、信息架构、视觉方向、页面、交互状态和验收标准。新版体验以网易云音乐的中文内容气质、情绪化表达和高效播放路径为主要参照，同时吸收 Spotify 在内容分层、卡片体系、播放连续性和资料库管理上的长处。

“对标”仅表示学习体验原则，不复制竞品商标、图标、插画、文案、专属版式或受版权保护的素材。OpenMusic 必须形成自己的品牌识别。

## 2. 产品目标

### 2.1 核心目标

- 用户打开应用后 3 秒内发现可播放内容，并可在 2 次点击内开始播放。
- 建立“发现—播放—收藏—再次收听”的完整闭环。
- 播放状态跨页面持续存在，切换页面不中断、不丢进度。
- 首页兼具中文音乐产品的亲近感和 Spotify 式清晰的内容货架结构。
- 在 ReactLynx 能力范围内实现稳定、流畅、可维护的原生感界面。

### 2.2 非目标（首期）

- 社交动态、评论区、直播、K 歌、商城、票务。
- 复杂会员支付体系和版权地区策略。
- 桌面端、多窗口、横屏专属设计。
- 逐像素复刻网易云音乐或 Spotify。

## 3. 用户与场景

核心用户为 16–35 岁中文音乐听众，包括通勤、学习、运动和睡前场景。典型任务：快速续播、浏览推荐、搜索歌曲/歌手/专辑、查看歌单、收藏内容、管理播放队列、跟随歌词。

关键体验指标：首播成功率、首播耗时、首页到播放转化率、搜索成功率、收藏率、次日再次播放率、播放错误率。

## 4. 体验原则

1. **音乐优先**：封面、标题和播放动作始终是视觉主角。
2. **熟悉但不仿制**：中文信息密度接近网易云音乐，结构秩序借鉴 Spotify，自有品牌贯穿颜色、形状和动效。
3. **一处播放、全局连续**：迷你播放器是所有主页面的常驻锚点。
4. **渐进呈现**：首页给结果，详情页给信息，更多菜单给低频动作。
5. **状态可感知**：加载、空态、失败、禁用、离线、正在播放均有明确反馈。
6. **可达与可读**：触控区、对比度、字号、动态效果适配不同用户。

## 5. 信息架构

底部一级导航固定为：

- **发现**：问候、快捷入口、个性推荐、最近播放、新歌/热门歌单。
- **搜索**：搜索框、历史记录、热搜、分类浏览、结果聚合。
- **音乐库**：收藏的歌曲、歌单、专辑、歌手及最近播放。
- **我的**：账号概览、下载入口（若支持）、播放与外观设置、关于。

全局层：迷你播放器、全屏播放页、播放队列、通用内容菜单、Toast/弹窗。

## 6. 品牌与视觉规范

### 6.1 视觉方向

关键词：克制、沉浸、温暖、年轻、内容驱动。默认深色主题，首期同时准备浅色 Token，避免组件写死颜色。

- 品牌主色：`#E83B45`（OpenMusic Red），用于主操作、播放态和小面积强调。
- 深色背景：`#0F1012`；一级表面：`#18191D`；二级表面：`#232429`。
- 主文字：`#F7F7F8`；次文字：`#A7A8AE`；弱文字：`#73757D`。
- 成功：`#39B980`；警告：`#F5A524`；错误：`#F04444`。
- 禁止大面积高饱和红底；红色强调面积建议不超过单屏 15%。
- 内容封面保持原始比例，不拉伸；歌单方形、歌手圆形、横幅圆角矩形。
- 背景可从当前封面提取低饱和颜色生成渐变，但必须保证文字对比度。

### 6.2 尺寸与排版

- 采用 4pt 基础栅格；常用间距 8/12/16/24/32。
- 页面水平安全边距 16；卡片圆角 10–14；按钮圆角 18–24。
- 中文字体使用平台默认无衬线；标题 24/30，分区标题 20/26，正文 16/22，辅助 13/18，标签 11/16。
- 正文最多 2 行，卡片标题通常 1 行；溢出省略，详情页可查看完整信息。
- 主要触控目标不小于 44×44；文字与背景满足 WCAG AA 对比度目标。

### 6.3 图标与动效

- 使用统一的圆角线性图标；选中态可用实心图标，不混用多套风格。
- 页面切换 180–240ms；按压反馈 80–120ms；底部播放器展开 280–360ms。
- 支持“减少动态效果”；无意义装饰不得持续动画。

## 7. 页面需求

### 7.1 启动与基础状态

- 启动页展示 OpenMusic 标记，完成本地状态恢复后进入主页。
- 首次使用不强制登录；游客可浏览和播放，收藏时提示登录或本地保存策略。
- 网络失败显示可重试状态；缓存内容仍可进入。

### 7.2 发现页

从上到下：顶部问候与头像；搜索快捷入口；2×N 快捷内容；焦点推荐；“为你推荐”；最近播放；精选歌单；新歌速递。

- 内容货架横向滚动，一屏露出下一张卡片边缘以暗示可滑动。
- “继续收听”优先于泛推荐；无历史时不显示该模块。
- 首屏骨架屏应稳定占位，避免内容加载后跳动。
- 点击卡片进入详情；播放按钮直接播放并保留当前上下文作为队列。

### 7.3 搜索页

- 搜索框进入页面自动聚焦；支持清空、取消和提交。
- 输入前展示历史、热搜和分类；输入时 300ms 防抖联想；提交后展示综合结果。
- 结果类型：单曲、歌手、专辑、歌单；综合页各展示摘要并提供“查看全部”。
- 无结果给出改写关键词建议；失败态提供重试；历史可逐条或全部清除。

### 7.4 歌单/专辑详情

- 顶部包含返回、封面、标题、创建者/歌手、简介摘要、统计信息。
- 主操作为“播放全部”，次操作包含收藏、更多；歌曲列表支持单曲菜单。
- 当前播放歌曲显示品牌色与等效器状态；不可播放项置灰并解释原因。
- 长列表必须分页或增量加载，保持滚动位置。

### 7.5 歌手详情

展示头像/主视觉、名称、关注状态、热门歌曲、专辑和相关内容。热门歌曲默认 5 首，可展开全部；点击歌手名或专辑具备明确返回路径。

### 7.6 音乐库

- 顶部筛选：全部、歌单、专辑、歌手；支持最近播放/最近添加/名称排序。
- 固定快捷入口“喜欢的音乐”和“最近播放”。
- 空态需提供去发现或搜索的行动按钮。
- 删除收藏是可撤销的轻操作；删除用户歌单等高风险动作必须二次确认。

### 7.7 迷你播放器

显示封面、歌曲名、歌手、播放/暂停和下一首；位于底部导航上方。点击主体展开全屏播放页；滑动行为若实现需保证与页面横滑不冲突。缓冲时播放按钮切换为进度状态，错误时可重试。

### 7.8 全屏播放页

- 顶栏：收起、播放上下文、更多。
- 主区：大封面；可切换到同步歌词。
- 信息区：歌曲名、歌手、收藏。
- 控制区：进度、已播/总时长、随机、上一首、播放/暂停、下一首、循环。
- 底部：音质/设备（能力允许时）、歌词、队列。
- 拖动进度时即时显示目标时间，松手后 seek；请求失败恢复并提示。
- 歌词自动定位当前行，手动滚动后短暂暂停自动跟随，并提供“回到当前歌词”。

### 7.9 播放队列

以底部抽屉或独立页呈现当前播放来源、当前歌曲和接下来播放。支持点选播放、移除、清空用户追加项；若运行时稳定支持拖拽，可提供排序，否则首期用上移/下移菜单替代。

### 7.10 我的/设置

包含账号入口、播放设置、音质、缓存、深浅色/跟随系统、语言、隐私、关于与版本。未实现的服务能力不得提供无效开关。

## 8. 通用交互与状态

- 返回遵循页面栈；再次点击当前 Tab 回到顶部；切换 Tab 保留各自滚动位置。
- 单曲菜单包含：下一首播放、添加到队列、收藏/取消收藏、查看歌手、查看专辑。
- 所有异步区域具备 loading/success/empty/error 四态。
- 乐观更新失败时回滚并提示；禁止重复提交。
- Toast 2–3 秒自动消失，重要错误保留可执行操作。
- 来电/音频焦点丢失时暂停或降级，恢复策略遵循平台规则。

## 9. 可访问性与本地化

- 图标按钮提供可读标签；状态不能只靠颜色表达。
- 支持系统字体缩放至 130% 时核心路径不截断。
- 读屏顺序与视觉顺序一致；进度条和切换按钮报告状态。
- 支持简体中文，文案不可拼接生成；时间、数字、复数由格式化层处理。

## 10. 性能与质量指标

- 冷启动可交互目标 ≤ 2.5 秒（中端设备、正常网络，不含首次大资源下载）。
- 页面切换和滚动目标 60fps，低端设备最低可接受 45fps。
- 首屏图片按显示尺寸加载；离屏图片延迟加载；列表避免全量渲染。
- 播放操作反馈 ≤ 150ms，网络播放开始目标 ≤ 1.5 秒。
- 崩溃率 < 0.2%；播放错误可被记录并定位。

## 11. 埋点

至少记录：`app_open`、`home_impression`、`content_click`、`search_submit`、`search_result_click`、`play_request`、`play_success`、`play_error`、`player_expand`、`seek`、`like_toggle`、`queue_open`、`queue_edit`。事件必须包含页面、内容类型、内容 ID、位置、播放来源和匿名会话 ID；不得记录搜索框外的自由文本或敏感身份信息。

## 12. 版本优先级

### P0（必须）

发现、搜索与结果、歌单/专辑详情、音乐库基础、迷你播放器、全屏播放、歌词、队列、深色主题、完整异步状态、基础埋点。

### P1（应有）

歌手详情、浅色主题、筛选排序、封面色渐变、动效降级、离线缓存入口。

### P2（可后续）

跨设备播放、个性化主题、桌面/平板布局、社交分享、高级推荐解释。

## 13. 验收标准

- 四个主 Tab、详情页、播放器和队列均能从真实或 Mock 数据完整走通。
- 任意页面发起播放后，迷你播放器、全屏播放器和队列状态一致。
- 页面切换、锁屏/后台后恢复时，当前歌曲和进度不出现明显错乱。
- 每个数据页面具备骨架、空态、错误与重试；断网无白屏。
- 主流程不存在不可点击的占位按钮；P1/P2 未实现功能需隐藏或标注。
- 常见 360–430dp 宽度设备无横向溢出；长中文/英文标题可控截断。
- 不出现网易云音乐、Spotify 的商标、Logo、受保护素材或暗示官方合作的文案。

## 14. 参考边界

Spotify 官方资料确认其核心能力包括 Home、Search、Your Library、Now Playing、Queue 和 Lyrics；这些只作为能力完整性参照。若未来接入 Spotify 数据，必须遵守其内容归属、元数据、封面和跳转规范。本期 OpenMusic UI 不依赖 Spotify 服务。

## 15. 产品战略补充：本地优先与双平台

### 15.1 产品定义

OpenMusic 不是某个在线音乐平台的换皮客户端，而是用户拥有和管理个人音乐资产的统一入口：本地歌曲在无账号、无网络时也能完整使用；在线内容、跨设备同步和商业服务均作为可插拔增强能力。

产品价值排序如下：

1. 本地音乐可靠播放、整理与检索。
2. Android 与 Windows 之间一致的音乐库和播放体验。
3. 可选的云同步、在线音源和增值服务。
4. 在不锁定用户数据的前提下实现可持续商业化。

### 15.2 平台范围

| 能力 | Android | Windows |
|---|---|---|
| 本地文件扫描 | 扫描授权目录，适配系统媒体权限 | 扫描用户选择的音乐文件夹 |
| 后台播放 | 通知栏、耳机按键、音频焦点 | 系统媒体控制、任务栏/托盘集成 |
| 导入方式 | 文件选择、目录授权 | 文件/文件夹选择、拖放导入 |
| 核心导航 | 底部四 Tab | 左侧导航 + 主内容区 + 底部播放栏 |
| 播放详情 | 全屏播放页 | 主内容页或右侧“正在播放”面板 |
| 快捷操作 | 长按、滑动、底部抽屉 | 右键菜单、悬停、键盘快捷键 |

两个平台必须共享功能语义、数据模型、品牌语言和播放状态，但允许采用符合平台习惯的布局，不要求像素级一致。

### 15.3 本地优先原则

- 首次启动允许直接进入，不强制注册或联网。
- 本地扫描、播放、搜索、歌单、收藏、歌词和基础设置离线可用。
- 用户选择扫描范围；应用不越权遍历无关目录。
- 原始音频文件不由应用擅自移动、改名或删除。
- 扫描结果、播放历史和用户编辑先写入本地数据库，再异步执行可选同步。
- 云端或在线服务不可用时，本地音乐库仍是完整可用产品，而不是降级占位页。

## 16. 本地音乐库需求

### 16.1 首次导入

首次进入音乐库时提供三个选择：“扫描音乐”“选择文件夹”“暂时跳过”。扫描前解释权限用途、支持格式和预计耗时；拒绝权限后仍可手动选择文件。

扫描过程展示已发现歌曲数、当前目录、进度和取消操作。取消后保留已经成功入库的结果。扫描完成展示新增、更新、跳过和失败数量，并允许查看失败原因。

### 16.2 扫描与去重

- 支持项目音频引擎实际可播放的主流格式；界面不得承诺未验证格式。
- 以稳定文件标识、路径、大小、修改时间及内容指纹组合去重。
- 文件移动或重命名后尽量识别为同一曲目，保留收藏、播放次数和歌单关系。
- 文件缺失时标记“文件不可用”，不立即清除用户数据；用户可重新定位或清理失效项目。
- 支持手动重新扫描，Windows 可选目录监控，Android 按平台限制进行增量同步。

### 16.3 元数据

读取标题、歌手、专辑、专辑艺术家、曲目号、碟号、年份、流派、时长、内嵌封面和歌词。缺失字段按“文件名 → 未知歌手 → 未知专辑”的降级规则展示。

用户可编辑曲目信息、封面和歌词。首期编辑默认只写 OpenMusic 数据库，不修改原文件；如未来支持写回标签，必须预览变更、备份并明确提示风险。

### 16.4 音乐库视图

提供歌曲、专辑、歌手、文件夹、歌单五种入口。支持按名称、添加时间、最近播放、播放次数、年份排序；支持多选并执行加入歌单、收藏、从资料库移除等批量动作。

“从资料库移除”只移除索引；“删除源文件”是单独的高风险操作，默认不提供，若实现必须二次确认并说明能否恢复。

## 17. Android 专属体验

- 获取媒体权限前先展示用途说明；适配平台分版本权限差异。
- 提供媒体通知：封面、标题、歌手、上一首、播放/暂停、下一首和关闭。
- 正确处理蓝牙/有线耳机控制、音频焦点、来电、其他应用抢占及拔出耳机。
- 后台播放不能依赖页面存活；被系统回收后可恢复当前歌曲、队列和进度。
- 适配状态栏、导航栏、刘海和手势安全区；360–430dp 为重点宽度。
- 小组件、车机和 Android Auto 不属于 P0，预留媒体会话能力。

## 18. Windows 专属体验

- 默认三栏结构：左侧主导航，中间内容，右侧可收起的播放详情/队列；窄窗口退化为两栏或单栏。
- 窗口最小推荐尺寸 900×600；低于断点时隐藏次要栏，不允许核心控制被裁掉。
- 支持拖入音频文件或文件夹、右键菜单、滚轮、悬停提示和系统文件选择器。
- 快捷键：空格播放/暂停，Ctrl+K 搜索，Ctrl+L 聚焦音乐库，Ctrl+O 导入，Ctrl+, 设置；输入框聚焦时不得错误触发播放快捷键。
- 关闭窗口行为可配置为退出或最小化到托盘；首次触发时解释当前设置。
- 支持系统媒体传输控制和任务栏媒体信息；多显示器和缩放比例变化后布局保持可用。

## 19. 在线能力与商业化边界

### 19.1 可插拔在线能力

在线搜索、推荐、歌词、封面、云盘或第三方音源必须通过 Provider 接入。每项内容清楚标识来源、可用地区和播放限制；Provider 不可用不得拖垮本地功能。

禁止通过规避 DRM、模拟未授权客户端或抓取受保护接口获得内容。接入任何商业平台前单独完成授权、隐私和品牌合规审查。

### 19.2 账号与同步

账号为可选增强功能。未登录用户拥有完整本地能力；登录可获得跨设备同步。同步对象可包括歌单、收藏、编辑后的元数据、播放进度与设置，默认不同步原始音频文件。

冲突规则必须可解释：歌单项目采用合并策略；删除使用墓碑记录；同一字段冲突以最新有效修改为主，并保留必要的恢复记录。

### 19.3 商业模式原则

- 可探索一次性买断、Pro 订阅或付费云同步。
- 本地文件播放、基础整理和导出不得被订阅锁定。
- 不在播放流程插入破坏性广告，不出售用户收听历史。
- 付费能力必须说明价值、价格、续费方式和数据退出方案。
- 用户可导出歌单与个人数据；取消服务后本地资料库继续可用。

## 20. 隐私、安全与数据所有权

- 权限最小化；所有权限均在触发相关功能时申请。
- 数据页展示本地索引、缓存、日志与同步数据的占用，并允许分别清理。
- 密钥和令牌使用平台安全存储，不写入日志、源码或普通配置文件。
- 诊断数据默认匿名化；崩溃上报、个性化推荐和使用分析提供清晰开关。
- 删除账号前说明云端删除范围、本地数据保留情况和生效时间。
- 提供数据库备份/导出与恢复能力，格式应可迁移且有版本号。

## 21. 补充业务指标

除第 3 节指标外，新增：本地扫描成功率、重复识别率、失效文件恢复率、离线播放成功率、跨端同步成功率、冲突率、音乐库规模下的搜索耗时、免费到 Pro 转化率及退款/取消原因。商业指标不得凌驾于播放可靠性和用户数据权利之上。

## 22. 更新后的交付路线

### M0：工程验证

验证 Android/Windows 的音频格式、后台能力、文件权限、数据库、虚拟列表和构建发布链路；产出能力矩阵，不承诺未经验证的功能。

### M1：本地播放器 MVP

双平台本地导入、音乐库、搜索、歌单、播放队列、歌词、断点恢复、深色主题和基础设置。无需账号即可完整使用。

### M2：体验完整化

增量扫描、元数据编辑、Windows 桌面交互、Android 媒体会话、浅色主题、数据导入导出、性能与可访问性完善。

### M3：可选云能力

账号、加密同步、冲突处理和设备管理。必须在 M1 稳定后启动。

### M4：合规在线内容与商业化

经授权的 Provider、Pro 权益和支付。单独完成法务、隐私、安全与商店审核。

## 23. 双平台最终验收补充

- 关闭网络后，已导入音乐仍可搜索、播放、加入歌单并显示本地歌词。
- 1 万首曲库完成扫描后，滚动、搜索和启动不出现不可接受卡顿。
- 文件新增、修改、移动、删除后，重新扫描结果正确且用户数据不无故丢失。
- Android 后台播放、通知控制、音频焦点和进程恢复通过设备测试。
- Windows 拖放、文件夹导入、快捷键、窗口缩放和系统媒体控制通过测试。
- 未登录、服务端故障或 Provider 故障均不影响本地播放闭环。
- 数据导出后可被重新导入；删除与清理操作范围明确且经过确认。
